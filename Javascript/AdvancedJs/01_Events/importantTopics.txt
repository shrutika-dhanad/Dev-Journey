1. What is an Event in JavaScript?

An event is an action or occurrence that happens in the browser and that JavaScript can detect and respond to.

For example:

User clicks a button → click event
User types in an input → input event
User submits a form → submit event
Mouse moves → mousemove event
Keyboard key is pressed → keydown event
Page finishes loading → load event

In simple language:

Event = Something happens, and JavaScript can execute code in response to it.

Because we are giving the function to addEventListener(), and JavaScript will call it when the event occurs.

});

Now the click won't continue bubbling to the parent through the normal propagation path.

This is very important for interviews and real projects.

JavaScript Events — Interview Questions

Now let's move to the interview part.

Beginner Questions
Q1. What is an event in JavaScript?

An event is an action or occurrence detected by the browser, such as a click, key press, form submission, mouse movement, or page loading.

Q2. What is an event handler?

An event handler is a function that executes when a particular event occurs.

button.addEventListener("click", handleClick);

function handleClick() {
    console.log("Clicked");
}
Q3. What is addEventListener()?

It is a method used to attach an event listener to an element.

element.addEventListener("click", handler);
Q4. What is the difference between onclick and addEventListener()?

onclick assigns one event handler and a later assignment can overwrite the previous one.

addEventListener() allows multiple listeners for the same event and provides options such as capture and once.

Q5. What is an event object?

It is an object automatically provided to an event handler that contains information about the event.

button.addEventListener("click", function (event) {
    console.log(event.type);
});
Q6. What is event.target?

It refers to the element where the event originally occurred.

Q7. What is event.currentTarget?

It refers to the element whose event listener is currently executing.

Q8. What is event bubbling?

Event bubbling is the process where an event propagates from the target element upward through its ancestors.

Child → Parent → Body → HTML → Document
Q9. What is event capturing?

Event capturing is the phase where an event travels from the outer ancestor elements toward the target.

Document → HTML → Body → Parent → Child
Q10. What is event delegation?

Event delegation is a technique where an event listener is attached to a parent element instead of multiple child elements, using event propagation to handle events from the children.

Intermediate Interview Questions
Q11. What is the difference between preventDefault() and stopPropagation()?
Method	Purpose
preventDefault()	Stops browser's default action
stopPropagation()	Stops event propagation
Q12. What is stopImmediatePropagation()?

It prevents the event from propagating and also prevents other listeners on the same element from executing after it.

Q13. What is the difference between target and currentTarget?
target
↓
Element where event originated

currentTarget
↓
Element whose listener is currently running
Q14. What is the difference between input and change?

input generally fires whenever the value changes during user input.

change fires when a value change is committed, with exact behavior depending on the form control.

Q15. What is DOMContentLoaded?

It fires when the HTML document has been completely parsed.

It doesn't wait for all images and external resources to finish loading.

Q16. What is the difference between load and DOMContentLoaded?
DOMContentLoaded
→ HTML parsing completed

load
→ Page and dependent resources loaded
Q17. What does { once: true } do?

It causes the listener to automatically stop listening after it executes once.

Q18. Why is event delegation useful?

It can reduce the number of event listeners, simplify code, and handle dynamically added child elements.

Q19. Why do we need to keep a function reference when using removeEventListener()?

Because the function passed to removeEventListener() must match the function object that was originally registered.

Q20. What happens if you use addEventListener("click", function(){}) multiple times?

Each listener is registered separately, so each callback can execute when the event occurs.

The event doesn't continue bubbling to the parent.

Q25. What is wrong here?
button.addEventListener("click", handleClick());

function handleClick() {
    console.log("Hello");
}

The function is being called immediately instead of being passed as the callback.

Correct:

button.addEventListener("click", handleClick);
