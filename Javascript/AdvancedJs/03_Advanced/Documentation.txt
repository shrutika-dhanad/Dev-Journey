37. readyState in XMLHttpRequest

This is an important interview topic.

XHR has different states.

0 → UNSENT
1 → OPENED
2 → HEADERS_RECEIVED
3 → LOADING
4 → DONE
0 — UNSENT

XHR created but open() hasn't been called.

const xhr = new XMLHttpRequest();
1 — OPENED

open() has been called.

xhr.open("GET", url);
2 — HEADERS_RECEIVED

Response headers have arrived.

3 — LOADING

Response body is being received.

4 — DONE

Request completed.

38. onreadystatechange

Older/common XHR pattern:

xhr.onreadystatechange = function () {

    if (xhr.readyState === 4) {

        console.log(xhr.responseText);

    }

};

More robust:

xhr.onreadystatechange = function () {

    if (
        xhr.readyState === 4 &&
        xhr.status === 200
    ) {
        console.log(xhr.responseText);
    }

};
39. Complete XHR example
const xhr = new XMLHttpRequest();

xhr.open(
    "GET",
    "https://jsonplaceholder.typicode.com/users"
);

xhr.onreadystatechange = function () {

    console.log("Ready State:", xhr.readyState);

    if (
        xhr.readyState === 4 &&
        xhr.status === 200
    ) {

        console.log(users);

    }

41. AJAX vs Fetch

Old style:

const xhr = new XMLHttpRequest();

xhr.open("GET", url);

xhr.onload = function () {
    console.log(xhr.responseText);
};

xhr.send();

Modern style:

fetch(url)
    .then(response => response.json())
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.log(error);
    });

And:

async function getUsers() {

    try {

        const response = await fetch(url);

        const data = await response.json();

        console.log(data);

    } catch (error) {

        console.log(error);

    }
}

For modern JavaScript development, Fetch + Promises + async/await are much more commonly used than raw XHR.

But XHR is still important to understand because it teaches you the fundamentals and appears in interviews/legacy code.

45. Interview Questions
Q1. What is AJAX?

Answer:

AJAX stands for Asynchronous JavaScript and XML. It is a technique that allows JavaScript to communicate with a server asynchronously and update parts of a webpage without requiring a complete page reload.

Q2. Is AJAX a programming language?

No.

AJAX is a technique/pattern.

Q3. Is AJAX an API?

Not exactly.

AJAX describes a technique. APIs such as XMLHttpRequest and fetch() can be used to implement that technique.

Q4. What is XMLHttpRequest?

XMLHttpRequest is a browser API used to make HTTP requests and receive responses asynchronously.

Q5. Does XMLHttpRequest only support XML?

No.

Despite its name, it can work with:

JSON
XML
Text
HTML
etc.
Q6. What is HTTP?

HTTP is a communication protocol used for transferring data between clients and servers.

Q7. What is the difference between request and response?

Request: Client → Server

Response: Server → Client

Client --Request--> Server
Client <--Response-- Server
Q8. What is console.log()?

It is a JavaScript console method used to output/log information, commonly for debugging.

Q9. Is console.log a debugger?

Not exactly.

It is a logging/debugging technique.

The browser's DevTools provide the actual debugging environment, including breakpoints, call stack, variable inspection, Network tools, etc.

Q10. What is V8?

V8 is Google's JavaScript engine, used in Chrome and Node.js. It is largely implemented in C++.

Q11. Is JavaScript a wrapper over C++?

No.

JavaScript is a programming language.

V8 is an implementation of JavaScript and is largely written in C++.

Q12. Where does XMLHttpRequest come from?

In a browser, XMLHttpRequest is provided by the browser's Web APIs/environment.

Q13. What is asynchronous programming?

It allows a task to start without blocking the execution of other work while waiting for the task to complete.

Q14. What is readyState?

It represents the current state of an XMLHttpRequest.

0 = UNSENT
1 = OPENED
2 = HEADERS_RECEIVED
3 = LOADING
4 = DONE
Q15. What is the difference between AJAX and Fetch?

AJAX is a technique/pattern.

fetch() is a modern browser API for making HTTP requests and is Promise-based.

What is an API?

API = Application Programming Interface

In simple words:

An API is a way for two different software systems to communicate with each other and exchange data or perform actions.

Marathi meaning

API म्हणजे दोन वेगवेगळ्या software/applications यांच्यामध्ये communication करण्यासाठी वापरला जाणारा interface.

सोप्या भाषेत:

एक application दुसऱ्या application कडून data मागते किंवा काही काम करून घेते, त्यासाठी API चा वापर होतो.

🍔 Real-life example

Imagine you go to a restaurant.

You
 ↓
Waiter
 ↓
Kitchen
 ↓
Waiter
 ↓
You

You don't directly enter the kitchen and tell the chef what to do.

The waiter acts as an interface between you and the kitchen.

Similarly:

Frontend
   ↓
   API
   ↓
Backend / Server
   ↓
Database

The API acts like the waiter.

Marathi
You = Frontend

Ingredients/storage = Database

Frontend directly database शी बोलत नाही. Usually frontend API मार्फत backend ला request करते.

API vs HTTP

Don't confuse these two.

API

Defines how software communicates.

HTTP

Is a protocol used for communication over the web.

So:

 ↓

Protocol used to send requests/responses
